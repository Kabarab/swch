# Моды SWCH — SDK 1.1

Мод может добавить тему, вкладки, действия или новый лаунчер. Код приложения
пересобирать не нужно. Поддерживаются Windows x64 и macOS ARM64.

SDK 1.1 сохраняет совместимость с модами для `^1.0.0`. Для новых файловых API,
фоновых заданий и `native_tools` указывай `api: "^1.1.0"`, чтобы прежние версии
SWCH показывали несовместимость. Неизвестные поля манифеста допускаются и не
меняют поведение известных полей; расширениям давай собственные имена.

## Установка и управление

Открой **Моды** в боковом меню. По умолчанию открывается подвкладка **Каталог**
с доступными расширениями и кнопками установки. В подвкладке **Установленные**
находятся скачанные моды, настройки, журнал и инструменты разработки. При установке SWCH предлагает
подтвердить доверие автору: серверный JavaScript работает с правами пользователя,
может читать файлы, обращаться к сети и запускать программы. Проверка каталога
проверяет структуру пакета и владельца GitHub-репозитория; она не проверяет
безопасность кода.

В разделе **Моды** можно совместить поиск с фильтрами по игре или приложению,
типу мода (интерфейс, тема, серверная часть), установке и совместимости с текущей
ОС и SDK. Сортировка — по названию или скачиваниям. В списке игр доступны и
игры из каталога, которых нет в твоей библиотеке; **Общие моды без привязки**
показывает расширения для SWCH в целом. **Сбросить фильтры** возвращает весь список.

В карточке мода показаны скачивания `mod.zip` из всех опубликованных стабильных
релизов его GitHub-репозитория. Это число загрузок ZIP, включая повторные загрузки,
проверки каталога и обновления; оно не равно числу пользователей или установок.
Статистика собирается при обновлении общего каталога (обычно раз в шесть часов)
и кэшируется приложением вместе с ним. Подсказка счётчика содержит время сбора.
При сбое сбора сохраняются прежние данные; если их ещё нет, показано **нет данных**.
Локальные ZIP и папки разработки не получают вымышленного счётчика.

Кнопка **Обновить** устанавливает новую версию вручную. Текущая операция мода
сначала завершается. SWCH проверяет SHA-256 и совместимость, запускает новую
версию и возвращает прежнюю, если активация не удалась. Прежний пакет находится
в `packages/<id>/previous`. Автоматических обновлений модов нет.

Отключение останавливает процесс мода и убирает его платформы из интерфейса,
сохраняя данные. Удаление убирает пакет; отдельная команда **Очистить данные**
доступна после удаления и очищает настройки, секреты, игры и аккаунты мода.
При падении открой журнал и нажми **Перезапустить**.

## Первый мод

Установи Node.js 24 на компьютер разработчика и получи папку `mod-sdk` из этого
репозитория. Для пользователей Node.js уже включён в сборку SWCH.

```powershell
node mod-sdk/cli.mjs init my-mod --template launcher --id alice.my-launcher
node mod-sdk/cli.mjs check my-mod
node mod-sdk/cli.mjs pack my-mod
```

Шаблоны: `theme`, `tab`, `launcher`. В папку копируется и GitHub Actions workflow
для выпуска `mod.zip`. Для локальной проверки подключи полный путь `my-mod`
через **Моды → Установка из ZIP и разработка → Подключить папку**.
После изменения файлов нажми **Перезагрузить**; исходная папка не копируется и
никогда не удаляется SWCH. Для запуска серверных модов из `cargo run` укажи путь
к Node.js 24:

```powershell
$env:SWCH_NODE_PATH = 'C:\path\to\node.exe'
cargo run
```

Шаблон лаунчера создаёт до двух демонстрационных аккаунтов. Подключи аккаунт,
загрузи библиотеку кнопкой рядом с Demo Launcher и открой игру из общей
библиотеки. Демонстрационный запуск создаёт отдельный короткоживущий процесс
Node.js; настоящие игровые клиенты и аккаунты не затрагиваются.

## Формат пакета

В корне ZIP находится `manifest.json`, без дополнительной внешней папки:

```json
{
  "id": "alice.my-launcher",
  "name": "My Launcher",
  "version": "1.0.0",
  "api": "^1.1.0",
  "platforms": ["windows-x64", "macos-arm64"],
  "description": "Описание мода",
  "backend": "backend.mjs",
  "ui": "index.html",
  "theme": "theme.json"
}
```

`backend`, `ui`, `theme` необязательны; нужен хотя бы один. ID — до 80 символов,
строчные латинские буквы, цифры, точки, дефисы и подчёркивания; первый символ —
буква или цифра. Пути относительные и переносимые между двумя ОС.
SWCH и CLI не задают квоты на размер ZIP, распакованных данных или число файлов.
Поддерживается ZIP64: мод может занимать 5 ГБ и больше при достаточном месте
на диске. Упаковка, загрузка и распаковка работают с файлами потоково,
без загрузки всего архива в оперативную память. При необходимости администратор
может задать собственные квоты через `SWCH_MOD_MAX_ZIP_BYTES`,
`SWCH_MOD_MAX_EXPANDED_BYTES`, `SWCH_MOD_MAX_FILES`; отсутствие значения или `0`
означает отсутствие квоты. Символические ссылки,
опасные пути и дубликаты путей без учёта регистра запрещены.

Обычные JavaScript-зависимости заранее включай в пакет, например в
`node_modules` после `npm ci --omit=dev`. На компьютере пользователя SWCH
не запускает `npm install` и установочные скрипты. Нативные Node.js-дополнения
`.node` запрещены. Для нативного кода используй отдельные инструменты из
`native_tools`, запускаемые дочерним процессом; зависимости от других модов
в v1 не поддерживаются. CLI не включает
`.git`, `.env`, `dist` и свою служебную папку `.swch-sdk`.

## Обложка мода

В `manifest.json` можно добавить необязательное поле `cover_url` с прямой
публичной HTTPS-ссылкой на картинку, например:

```json
"cover_url": "https://raw.githubusercontent.com/alice/my-mod/main/cover.png"
```

Каталог показывает моды сеткой карточек с постерами, как в библиотеке игр.
Рекомендуемое соотношение сторон обложки — 2:3. Ссылка должна быть без логина и пароля,
без пробельных и управляющих символов, длиной до 2048 байт UTF-8. Обложка видна
в каталоге и в установленных модах. CLI проверяет поле при упаковке; чтобы
обновить обложку опубликованного мода, выпусти новую версию пакета.

Если поле отсутствует или картинка не загрузилась, показывается аватар
владельца GitHub-репозитория. Для локального ZIP или папки разработки без
известного репозитория используется общий аватар GitHub. Если недоступен и
GitHub, карточка показывает встроенное изображение мода.

## Привязка к игре или приложению

В карточке установленного мода нажми **Игры и приложения**, отметь нужные игры
из библиотеки и нажми **Сохранить привязку**. Можно выбрать несколько игр.
Привязка сохраняется после перезапуска SWCH и обновления мода. Кнопка
**Как указал автор** восстанавливает список из манифеста; снятие всех отметок
убирает мод со страниц игр, оставляя его в общем разделе **Моды**.

Открой игру в библиотеке и нажми **Моды**: здесь показаны её установленные моды
(включая отключённые) и подходящие моды из каталога. **Открыть** запускает вкладку
включённого мода. **Все моды** возвращает полный список.
Открывается тот же общий раздел **Моды** с выбранной игрой в фильтре; фильтр
можно сменить или сбросить прямо там.

Автор объявляет привязку в необязательном поле `games` манифеста.
Эта привязка входит в опубликованный пакет и каталог и применяется у всех
пользователей. Выбор **Игры и приложения** в установленной карточке изменяет
только локальное переопределение и не меняет опубликованный манифест.

Пример:

```json
"games": [
  {"launcher": "hoyoverse", "app_id": "genshin", "name": "Genshin Impact"},
  {"launcher": "steam", "app_id": "2767030", "name": "Marvel Rivals"}
]
```

Это фрагмент `manifest.json`. Игра определяется точной парой `launcher` +
`app_id` из `library.list()`, а `name` служит подписью. Одинаковые ID в разных
лаунчерах относятся к разным играм; для версии игры из другого магазина добавь
отдельную запись. Поддерживаются и платформы модов (`mod:author.mod:launcher`).
Количество уникальных привязок не ограничено. Отсутствие `games` означает общий мод.

При открытии вкладки из игры `window.swch.game` содержит выбранную игру,
`window.swch.account` — публичные поля выбранного аккаунта или `null`.
При открытии из общего раздела или бокового меню оба поля равны `null`.
Контекст фиксируется на момент открытия. Действия из карточки мода на странице
игры получают `{game, account}` в аргументе обработчика; из общего списка — `{}`.

```javascript
const game = window.swch.game;
const account = window.swch.account;
const result = await swch.call('action', {
  id: 'inventory',
  input: {game, account}
});
```

Привязка создаёт переход к расширению. Загрузку инвентаря, персонажей или других
данных реализует сам мод; доступ к данным конкретной игры определяется её API
и авторизацией пользователя.

## Серверный SDK

Серверная точка входа экспортирует функцию активации. SDK передаётся аргументом;
установленная npm-библиотека для исполнения не требуется:

```javascript
export default async function activate(swch) {
  swch.registerAction({id: 'hello', name: 'Привет'}, async () => {
    return {message: 'Привет из мода'};
  });
}
```

Регистрируй вкладки, действия и лаунчеры во время активации. Каждое объявление
имеет локальный ID и название. Вкладке нужен `ui` в манифесте.

| API | Назначение |
| --- | --- |
| `library.list()` | Игры из базы SWCH |
| `library.refreshSteam({account_id?})` | Обновление Steam через штатный путь SWCH |
| `accounts.list()` | Публичные данные аккаунтов, без токенов |
| `storage.get/set/delete(key, value)` | Собственное JSON-хранилище без квоты SWCH |
| `settings.get/set(value)` | Настройки мода как JSON-объект |
| `secrets.get/set/delete(key, value)` | Секреты в системном хранилище учётных данных |
| `events.on(event, listener)` | Подписка; возвращает функцию отмены |
| `events.emit(event, data)` | Событие в пространстве имён мода |
| `registerTab(metadata)` | Вкладка с интерфейсом мода |
| `registerAction(metadata, handler)` | Кнопка действия на странице модов |
| `registerMethod(id, handler)` | Внутренний метод мода без кнопки на карточке |
| `registerLauncher(metadata, handlers)` | Новая платформа |
| `files.paths()/usage()` | Пути и занятое место для данных, кэша, временных файлов и инструментов |
| `files.configure(kind, directory)` | Перенос категории из интерфейса, с остановкой и перезапуском мода |
| `files.clearCache()` | Очистка кэша без удаления постоянных данных |
| `jobs.register/start/list/get/cancel` | Фоновые задания с прогрессом и восстановлением |
| `tools.list/run/status/stop` | Проверенные нативные инструменты и принадлежащие моду процессы |
| `dialogs.openFile/openFolder` | Системный выбор файлов или папки |
| `shell.openFolder(path)` | Открыть папку в Проводнике или Finder |
| `clipboard.readText()/writeText(text)` | Текст системного буфера обмена |
| `log(...args)` | Запись в журнал |

Ключи хранилища используют тот же формат, что ID. Хранилище переживает
отключение, обновление и удаление пакета. События `library.changed` и
`accounts.changed` сообщают о выполненных изменениях в SWCH. Собственные
события автоматически получают префикс `mod:<id>:`; собственному интерфейсу
и серверному коду мода они доставляются с исходным коротким именем.

Типы находятся в `mod-sdk/index.d.ts`. Серверный протокол — JSON-RPC 2.0,
по одному JSON-сообщению на строку stdin/stdout. `console.log` перенаправляется
в stderr. SWCH не задаёт квоту на размер сообщения или общий таймаут запроса;
длительные действия и активация могут завершаться столько, сколько нужно моду.
Это относится и к вызовам из iframe. Фоновые обращения к SDK обслуживаются
постоянно. Для собственных сетевых запросов и дочерних процессов мод сам
определяет отмену, таймауты и обработку ошибок. Фактический объём JSON ограничен
доступной памятью процесса, а сохранённых данных — свободным местом на диске.

Рабочая папка процесса — собственная папка данных мода, чтобы запущенная игра
не блокировала обновление пакета в Windows. Для ресурсов используй
`new URL('./resource', import.meta.url)` или `SWCH_MOD_PACKAGE_DIR`;
`SWCH_MOD_DATA_DIR` указывает на постоянную папку данных.

Для операции интерфейса, которая не должна создавать кнопку на карточке,
регистрируй внутренний метод:

```javascript
export default function activate(swch) {
  swch.registerMethod('refresh', async ({account_id} = {}) => {
    await swch.library.refreshSteam({account_id});
    return swch.library.list();
  });
}
// В интерфейсе:
const games = await swch.call('method', {id: 'refresh', input: {}});
```

`registerAction` по-прежнему создаёт видимое действие. Для чтения и обновления
встроенной библиотеки используй SDK, без прямого изменения базы данных SWCH.

## Файлы и выбор диска

`files.paths()` возвращает абсолютные пути `{data, cache, temp, tools}`.
Это отдельные папки: постоянные документы и большие загруженные ресурсы хранятся
в `data`, восстанавливаемые загрузки — в `cache`, промежуточные файлы — в `temp`,
установленные нативные инструменты — в `tools`. `files.usage()` возвращает
занятые байты по тем же четырём ключам. JSON-хранилище, секреты и служебные
индексы заданий управляются SWCH отдельно.

В карточке установленного мода открой **Файлы и место на диске**. Здесь видны
пути и размер каждой категории; можно выбрать папку на другом диске, открыть
её в файловом менеджере и очистить кэш. Управление файлами доступно и у
отключённого мода. При смене папки SWCH останавливает активный мод, переносит
файлы и запускает его вновь. Выбранная родительская папка остаётся пользовательской;
файлы размещаются в её подпапке `SWCH-Mods/<mod-id>/<kind>`.

Те же действия можно сделать из интерфейса мода:

```javascript
let paths = await swch.call('files.paths');
const usage = await swch.call('files.usage');
const directory = await swch.call('dialogs.openFolder', {title: 'Папка ресурсов'});
if (directory) {
  paths = await swch.call('files.configure', {kind: 'data', directory});
}
await swch.call('shell.openFolder', {path: paths.data});
await swch.call('files.clearCache');
```

`files.configure` вызывается через интерфейс или настройки SWCH. Из серверного
процесса мода вызов отклоняется: процесс не может переносить собственную рабочую
папку во время исполнения. Для файлов backend используй свежий результат
`files.paths()`; после переноса процесс получит обновлённый `SWCH_MOD_DATA_DIR`.

`dialogs.openFile({title?, multiple?, extensions?})` возвращает массив полных
путей; отмена — пустой массив. `dialogs.openFolder({title?})` возвращает путь
или `null` при отмене. Например, `extensions: ['zip', 'json']` задаёт фильтр
диалога. `clipboard.readText()` и `clipboard.writeText(text)` работают с текстом.
Диалоги и буфер доступны на Windows и macOS; отмену обрабатывай как обычный
результат и открывай системные окна после явного действия пользователя.

## Фоновые задания

Длительные загрузки и обработку файлов оформляй через `jobs`, чтобы интерфейс
получал ID операции и мог показать прогресс, отменить её и прочитать результат:

```javascript
export default function activate(swch) {
  swch.jobs.register('import', async ({files}, job) => {
    const start = Number(job.savedCheckpoint?.next || 0);
    for (let i = start; i < files.length; i++) {
      job.signal.throwIfAborted();
      // Здесь асинхронная обработка очередного файла мода.
      await job.checkpoint({next: i + 1});
      await job.progress({done: i + 1, total: files.length});
    }
    return {processed: files.length};
  });
}
// В интерфейсе:
const job = await swch.call('jobs.start', {type: 'import', input: {files: []}});
swch.on('jobs.changed', updated => renderProgress(updated));
const saved = await swch.call('jobs.get', {id: job.id});
// По действию пользователя:
await swch.call('jobs.cancel', {id: job.id});
```

`jobs.start(type, input)` в backend возвращает тот же объект задания;
`jobs.list()` и `jobs.get(id)` читают сохранённое состояние. Поля объекта:
`id`, `type`, `status`, `input`, `progress`, `checkpoint`, `result`, `error`,
`created_at`, `updated_at`, `attempt`. Статусы: `queued`, `running`, `completed`,
`failed`, `cancelled`. Контекст обработчика содержит `id`, `signal`, `attempt`,
`savedCheckpoint`, асинхронные `progress(value)` и `checkpoint(value)`.

После перезапуска незавершённые `queued`/`running` задания возобновляются после
активации мода. Сохраняй контрольную точку после завершённого шага и делай
повторную обработку безопасной: SWCH хранит состояние, а логику возобновления
выполняет автор. Для загрузок передавай `job.signal` в `fetch` и потоки; при
запуске инструмента связывай отмену с `tools.stop(process_id)`. Тяжёлый синхронный
JavaScript блокирует цикл событий Node.js — используй `worker_threads` или
отдельный нативный процесс, чтобы отмена и SDK оставались отзывчивыми.

## Нативные инструменты

Исполняемые файлы объявляются в `native_tools`; `.node`-дополнения запрещены.
Для каждого инструмента укажи ID, целевую платформу, версию, лицензию и файлы
с SHA-256. `path` задаётся от корня пакета, а `executable: true` явно разрешает
запуск файла:

```json
"native_tools": [{
  "id": "processor",
  "platform": "windows-x64",
  "version": "1.0.0",
  "license": "MIT",
  "files": [{
    "path": "native/windows-x64/processor.exe",
    "sha256": "<64 hex digits of the actual file SHA-256>",
    "executable": true
  }]
}]
```

Для `macos-arm64` добавь отдельную запись с подходящими двоичными файлами.
Включай в список также библиотеки и другие необходимые файлы; для них не ставь
`executable`. SWCH проверяет хеши, копирует файлы в отдельную папку версии внутри
`tools` и выставляет обычные права `0755` для исполняемых файлов, `0644` для данных
на macOS. Учитывай лицензии, архитектуру и системные требования каждого инструмента.

```javascript
const installed = await swch.tools.list();
const {process_id} = await swch.tools.run('processor', ['--input', 'resource.bin']);
const processes = await swch.tools.status();
await swch.tools.stop(process_id);
```

Если в инструменте несколько исполняемых файлов, передай третьим аргументом
`{executable: 'native/windows-x64/processor.exe'}`. Аргументы передаются массивом
без shell; перед запуском хеш исполняемого файла проверяется вновь. Рабочая
папка — `data` мода. `run` возвращает ID процесса, `status` — состояние и код
завершения. Для обмена данными используй свои файлы или протокол инструмента;
этот API не перенаправляет stdout в интерфейс.

SWCH владеет процессами через Windows Job Object и группы процессов Unix.
При отключении, удалении, перезагрузке мода или аварийном завершении runtime
управляемые процессы и их потомки завершаются. Сам мод должен корректно
освобождать ресурсы и обрабатывать отмену задания.

## Лаунчеры

```javascript
export default function activate(swch) {
  swch.registerLauncher({
    id: 'demo', name: 'My Launcher',
    capabilities: ['library', 'launch']
  }, {
    async library() {
      return [{id: 'game-1', app_id: 'game-1', name: 'My Game', is_installed: true}];
    },
    async launch({game_id, account_id}) {
      // Запуск через API сервиса или официальный клиент.
      return {message: `Запуск ${game_id}`};
    }
  });
}
```

Обработчики `library` и `sync` возвращают массив игр; `accounts` — массив
аккаунтов. Для каждой объявленной возможности нужен соответствующий обработчик.
`connect` получает объект параметров, `disconnect` и `switch` — `account_id`,
`launch` — `game_id` и необязательный `account_id`.

Игре нужны `id`, `name`; остальные поля описаны в TypeScript-типах. `owner_ids`
содержит локальные ID владельцев, которых сначала нужно получить через
`accounts`. Аккаунту нужны `id`, `username`; одновременно активен максимум один
аккаунт платформы. После `connect`, `disconnect` и `switch` SWCH автоматически
вызывает `accounts`, если эта возможность объявлена.

SWCH присваивает платформе ID `mod:<mod-id>:<launcher-id>`, игре —
`<platform-id>:game:<local-id>`, аккаунту — `<platform-id>:account:<local-id>`.
При вызове обработчиков SDK возвращает локальные ID. Чужие идентификаторы
отклоняются. Синхронизация заменяет только записи соответствующей платформы
в транзакции; владение играми сохраняется вместе с библиотекой.

## Интерфейс и темы

`ui` — самостоятельный HTML-документ с включёнными стилями и скриптами.
Интерфейс открывается в изолированном iframe без доступа к DOM основного окна.
CSS, JavaScript-модули, изображения, шрифты, WASM и другие файлы можно хранить
рядом с HTML или в подпапках пакета и подключать относительными путями. SWCH
добавляет базовый URL папки HTML: для `ui: "web/index.html"` ссылка `./app.js`
загрузит `web/app.js`. Сборка всего интерфейса в один HTML не требуется.

`window.swch.assets.url('models/model.wasm')` возвращает абсолютный URL файла
от корня пакета; его можно передать в `fetch`, загрузчик WASM или элемент
интерфейса. Используй относительные пути без `..`, абсолютных путей и URL схем.
SWCH раздаёт только обычные файлы активного пакета, проверяет итоговый путь
и запрещает выход из его папки, в том числе через символические ссылки.
Скрытые служебные файлы не раздаются. Потоковые HTTP-ответы поддерживают Range
и тип содержимого; для шрифтов и модулей разрешён CORS из изолированного iframe.

В iframe есть `window.swch.call(method, params)` и `window.swch.on(event, listener)`:

```javascript
const games = await swch.call('library.list');
const count = await swch.call('action', {id: 'count', input: {}});
swch.on('library.changed', () => refreshMyView());
```

Настройки: `settings.get`, `settings.set` с `{value: {...}}`.
Хранилище: `storage.get/set/delete` с `{key, value}`.
Имя выбранной вкладки находится в `window.swch.tab`.

Тема — JSON-объект. Поддерживаются `bg`, `panel`, `panel-hover`, `line`, `text`,
`muted`, `accent` в формате `#RRGGBB` и `radius` от `0px` до `32px`.
Кнопка **Применить тему** выбирает одну активную тему; **Стандартная тема**
возвращает обычное оформление. Произвольный CSS в основное окно не внедряется.

## Публикация через GitHub

1. Создай публичный репозиторий в своём личном GitHub-аккаунте и добавь файлы мода.
2. Установи `version` в манифесте и выпусти тег `vX.Y.Z`. Шаблон workflow создаст
   стабильный GitHub Release с `mod.zip`.
3. В `Kabarab/swch` открой Issue Form **Publish a SWCH mod**, укажи `owner/repository`.
   Заявку отправляет владелец репозитория.
4. Actions проверит структуру ZIP, аккаунт владельца, соответствие версии тегу,
   вычислит SHA-256 и добавит запись в каталог без ручного одобрения.

Один репозиторий публикует один мод. Каталог связывает ID мода с числовыми ID
репозитория и владельца. Организации, приватные и архивные репозитории не
поддерживаются. Не заменяй содержимое выпущенного `mod.zip`: версия и её хеш
сохраняются в истории каталога. Для любых изменений выпусти новую версию.
Будущие стабильные релизы проверяются каждые шесть часов. Предрелизы пропускаются.

Чтобы старые строгие клиенты могли прочитать общий каталог, его `manifest`
содержит известные им основные поля, а новые поля публикуются рядом в
`manifest_extensions`. Клиент с SDK 1.1 объединяет их перед проверкой совместимости.
Старый клиент видит требование `^1.1.0` и пропускает неподдерживаемый мод;
весь каталог остаётся читаемым. Сам `manifest.json` внутри ZIP содержит полный
манифест; создавать `manifest_extensions` автору вручную не нужно.

У хостинга остаются собственные ограничения: [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)
принимает отдельный файл меньше 2 GiB. Большой локальный `mod.zip`, например
5 ГБ, устанавливай через **Установка из ZIP** или подключай папку разработки;
ресурсы также можно загружать самим модом в его папку данных. Этот лимит GitHub
не является ограничением размера установленного мода в SWCH.

## Подключение каталога владельцем SWCH

После публикации этих изменений в основной ветке запусти workflow
**SWCH mod catalog** один раз. Он создаст ветку `mod-catalog` и корневой
`index.json`. Заявки Issues и расписание затем обновляют только эту ветку.
Нужны включённые GitHub Actions и разрешённые репозиторные токены на запись
содержимого и Issues. Пользовательский токен и отдельный сервер не нужны.

Начальный каталог находится в `catalog/index.json`, список блокировки —
`catalog/blocked.json` в основной ветке. Добавление ID в список запрещает новые
установки из каталога. Для срочного применения запусти workflow вручную.
Уже установленные моды не удаляются автоматически.

Валидатор использует только код SWCH из основной ветки, не скачивает исходники
автора и не выполняет код пакета. Данные Issues читаются из JSON-события,
не подставляются в shell-команды. Аккаунт GitHub подтверждает владельца
репозитория, но не безопасность его программы.

## Хранилище и проверки

Данные модов находятся в `<config-dir>/swch/mods`; путь можно изменить через
`SWCH_MODS_DIR`. Пакеты, состояние, данные и кэш каталога разделены. Секреты
находятся в системном keyring, игры и аккаунты — в базе SWCH с собственными
пространствами имён. API управления модами принимает только локальный origin
SWCH, чтобы сторонняя веб-страница не могла установить мод.

```powershell
$env:SWCH_TEST_NODE = 'C:\path\to\node.exe'
cargo test --lib mods::
cargo test --test mods_tests --test mod_jobs_tests --test mod_assets_tests --test mod_large_packages_tests --test mod_native_tools_tests
node --test tests/mod-sdk.test.mjs tests/mod-jobs-sdk.test.mjs tests/mod-runtime.test.mjs
node tests/ui/run-regressions.cjs
```

Для отдельной проверки настоящего файла на 5 ГиБ при достаточном месте на диске:

```powershell
cargo test --test mod_large_packages_tests real_five_gib -- --ignored
```

Node.js для релизов закреплён в `mod-sdk/runtime-lock.json` вместе с контрольными
суммами официальных файлов. `scripts/bundle-mod-runtime.mjs` проверяет хеш перед
добавлением runtime в Windows ZIP и macOS bundle. CI проверяет движок модов
на Windows и macOS; локально на Windows macOS-тесты не выполняются.

## Завершение серверного мода

`activate(swch)` может вернуть асинхронную функцию завершения. SWCH вызывает
её перед отключением, удалением, перезагрузкой и штатным завершением сервера.
Тип `Activate` разрешает `void`, `Cleanup` или `Promise<void | Cleanup>`;
`Cleanup` — `() => void | Promise<void>`. Она должна освободить дочерние процессы
и открытые файлы за 10 секунд.
SWCH завершает дерево принадлежащих моду процессов и при аварии Node.js,
когда функция завершения не вызывается. У `tools.run` stdin закрыт;
инструменты получают аргументы и работают с файлами. Собственные работники,
запущенные напрямую через Node.js с протоколом stdin, могут дополнительно
использовать закрытие канала как сигнал завершения.

Официальный автоклеймер распространяется отдельным ZIP; исходники и сборка
описаны в [mods/autoclaimer/README.md](../mods/autoclaimer/README.md).
