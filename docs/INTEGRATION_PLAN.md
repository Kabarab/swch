# План интеграции: swch → мульти-лаунчер

**Статус:** Draft для ревью. Кода в этом шаге нет — только архитектурное решение.
**Цель:** объединить в swch три контура — переключатель аккаунтов (концепция TcNo-Acc-Switcher), агрегатор библиотек (концепция Playnite) и фоновый клеймер бесплатных игр (free-games-claimer) — по модели Heroic Games Launcher: независимые модули-воркеры под капотом, общающиеся с UI через единый шлюз.

---

## 0. Аудит текущего состояния (что уже есть)

Хорошая новость: все три контура в проекте уже существуют в зачаточном виде. Мы не строим с нуля — мы разделяем, укрепляем и связываем.

| Контур | Что уже есть | Чего не хватает |
|---|---|---|
| **Account Switcher** | `interfaces.PlatformProvider.SwitchAccount()`, generic-своппер `internal/scanner/fileswap.go` (бэкап/рестор файлов как в TcNo), нативный Epic-клиент с device auth (`internal/epic/`), kill-процессов в `internal/sys/` | Шифрование снапшотов сессий (PRD 3.2: DPAPI/Keychain — сейчас файлы копируются в открытом виде), своп веток реестра Windows, единообразие (Roblox живёт вне provider-модели) |
| **Library Aggregator** | `App.GetLibrary()` параллельно опрашивает 8 провайдеров и мержит в `models.LibraryGame` c `AvailableOnAccounts` | Персистентный кэш (сейчас полный рескан на каждый вызов), фоновое обновление, получение **удалённых** библиотек по каждому сохранённому аккаунту (есть только у Epic через API и частично у Steam через XML-профили), дедупликация одной игры из разных магазинов |
| **Free Games Claimer** | Вендоренный форк vogler/free-games-claimer в `tools/free-games-claimer/` (Node + playwright-core + cloakbrowser), запуск из `app.go` как child-process, стрим логов через Wails events, профили аккаунтов, 2FA через Telegram | Планировщик (сейчас только ручной запуск), история заклеймленных игр, фоновый режим (tray), извлечение результатов из stdout |

**Главная архитектурная проблема:** `internal/app/app.go` — god-object на ~1500 строк. В нём смешаны: UI-фасад (42 bound-метода), бизнес-логика агрегации, управление child-процессами клеймера, Telegram-поллинг и монитор игровых сессий. Прежде чем наращивать функционал, это нужно разрезать на сервисы — иначе каждая новая фича будет умножать хаос.

Прочие находки:
- Фронтенд — **vanilla JS** (`frontend/src/main.js`, 1261 строка) + Vite. GEMENI.MD заявляет React, но его в коде нет. Это нужно учесть: миграцию на React в этот план **не включаем** (отдельное решение).
- Настройки пишутся в **CWD** (`accounts_settings.json` и т.д. в корне репозитория) — для установленного приложения это сломается; нужен переезд в `os.UserConfigDir()/swch` с миграцией.
- `tools/windows/legendary.exe` (8 МБ, раннер Heroic для Epic) лежит в репо, но **нигде не используется** в Go-коде — это готовый кандидат на роль воркера установки/загрузки игр Epic в Phase C.
- `tools/switcher.exe` + `*.cs` — легаси C#-свитчеры; `runCSharpSwitcher` из основного флоу уже не вызывается → депрекейтим.

## 1. Целевая архитектура (модель Heroic)

У Heroic: UI (React) ⇄ IPC ⇄ main-процесс ⇄ внешние CLI-раннеры (legendary, gogdl, nile). Перекладываем на стек Wails:

```
┌────────────────────────────────────────────────────────────┐
│  frontend/ (Vite, vanilla JS, модули по вьюхам)            │
│    ▲ Wails events (async push: прогресс, логи, статусы)    │
│    │ Wails bindings (sync запрос/ответ)                    │
└────┼───────────────────────────────────────────────────────┘
     ▼
┌────────────────────────────────────────────────────────────┐
│  internal/app/  — ТОНКИЙ ФАСАД (только bound-методы,       │
│                   делегирование в сервисы)                 │
└────┬───────────────────────────────────────────────────────┘
     ▼
┌────────────────────────────────────────────────────────────┐
│  internal/services/  — НЕЗАВИСИМЫЕ ВОРКЕРЫ                 │
│   ├─ library/   агрегатор + кэш + фоновый refresh          │
│   ├─ switcher/  оркестрация смены аккаунтов                │
│   ├─ claimer/   супервизор Node-процессов + планировщик    │
│   └─ monitor/   трекинг игровых сессий (playtime)          │
│         │  events через internal/bus (абстракция над       │
│         │  wails runtime → сервисы тестируемы без UI)      │
└────┬────┴──────────────────────────────────────────────────┘
     ▼
┌────────────────────────────────────────────────────────────┐
│  ПРОВАЙДЕРЫ ПЛАТФОРМ (без изменений концепции)             │
│   internal/scanner/*  + internal/epic/                     │
│   контракт: interfaces.PlatformProvider (+ новые           │
│   опциональные capability-интерфейсы)                      │
├────────────────────────────────────────────────────────────┤
│  ОС-СЛОЙ: internal/sys, internal/registry,                 │
│           internal/vault (НОВЫЙ: шифрование сессий)        │
├────────────────────────────────────────────────────────────┤
│  ВНЕШНИЕ РАННЕРЫ (аналог legendary/gogdl у Heroic):        │
│   node tools/free-games-claimer/*.js  (клеймер)            │
│   tools/windows/legendary.exe         (Epic, Phase C+)     │
└────────────────────────────────────────────────────────────┘
```

Ключевая идея: **фасад `App` остаётся единственной точкой биндинга в Wails** — фронтенд-контракт не ломается, текущий UI продолжает работать на каждом шаге рефакторинга. Сервисы не знают про Wails напрямую: они получают интерфейс `bus.Emitter`, что выполняет требование PRD по тестируемости (моки вместо UI).

## 2. Раскладка по папкам и файлам

### 2.1. Новые пакеты в `internal/`

| Пакет | Файлы | Назначение |
|---|---|---|

| `internal/services/claimer/` | `runner.go`, `config.go`, `telegram.go`, `scheduler.go`, `history.go` | Переезд ~600 строк из app.go: `RunClaimerScript`, `StopClaimerScript`, `ensureDependencies`, `getClaimerPath`, `parseEnvFile`/`writeEnvFile`, Telegram-2FA. **Новое:** `scheduler.go` — фоновый запуск по расписанию; `history.go` — парсинг stdout клеймера → история полученных игр. |
| `internal/services/library/` | `service.go`, `cache.go`, `merge.go`, `refresh.go` | Переезд `App.GetLibrary()`. **Новое:** персистентный кэш (SQLite), фоновый refresh-воркер с прогресс-событиями, дедупликация одной игры из разных магазинов (нормализация названий, как у Playnite). |

| `internal/services/monitor/` | `monitor.go` | Переезд `monitorGameSession` (трекинг playtime) из app.go. |
| `internal/vault/` | `vault.go`, `vault_windows.go`, `vault_darwin.go` | **Новое:** шифрование снапшотов сессий (PRD 3.2 "Store"). Windows — DPAPI (код уже есть в `internal/epic/crypto_windows.go`, обобщаем и переносим сюда); macOS — Keychain через `/usr/bin/security` (без новых зависимостей; подход уже опробован в `find_epic_keychain.sh`). |

### 2.2. Изменения в существующих файлах

| Файл | Что меняется |
|---|---|
| `internal/app/app.go` | Худеет до ~300–400 строк: структура `App` держит ссылки на сервисы, bound-методы становятся однострочными делегациями. **Сигнатуры существующих методов не меняются** — фронтенд и сгенерированные биндинги не ломаются. Добавляются новые методы: `RefreshLibrary()`, `GetWorkersStatus()`, `SetClaimerSchedule()`, `GetClaimHistory()`, `SnapshotAccount()`. |
| `main.go` | Сборка сервисов (DI вручную), `OnShutdown` для graceful-остановки воркеров (сейчас его нет — клеймер-процесс может осиротеть), опционально systray для фонового режима (Phase D). |
| `internal/interfaces/provider.go` | `PlatformProvider` **не трогаем** (9 реализаций продолжают компилироваться). Добавляем опциональные capability-интерфейсы, проверяемые через type assertion — стандартный Go-паттерн "interface upgrade": `RemoteLibraryProvider` (владение играми по сохранённому аккаунту), `SessionSnapshotter` (Save/Restore/List/Delete снапшотов), `ProcessController` (Kill/Start лаунчера). |
| `internal/scanner/fileswap.go` | Снапшоты прогоняются через `internal/vault` (шифрование); добавляется поддержка веток реестра Windows (export/import через `internal/registry`) — это закрывает TcNo-кейсы для лаунчеров, хранящих сессию в реестре. |
| `internal/scanner/roblox.go` | Оборачивается в `PlatformProvider` (сейчас единственный, кто торчит из общей модели — в app.go для него ручные ветки). |
| `internal/settings/manager.go` | Переезд хранения из CWD в `os.UserConfigDir()/swch/` с одноразовой миграцией старых файлов. Новые структуры: `ClaimerSchedule`, ссылка на library-кэш. |
| `internal/sys/sys_*.go` | Обобщение `KillSteam`/`KillEpic`/`KillRiot` → `KillProcesses(names []string)` для обеих ОС (сейчас fileswap убивает процессы только на Windows). |
| `frontend/src/main.js` | Разрезается на модули (это не миграция на фреймворк, просто декомпозиция): `src/api.js` (обёртка над wailsjs-биндингами), `src/events.js` (зеркало констант из `internal/bus/events.go`), `src/views/library.js`, `src/views/accounts.js`, `src/views/claimer.js`, `src/views/tasks.js` (**новая** вьюха — статусы воркеров). |
| `frontend/index.html` | Новая секция `view-tasks` (статус воркеров, расписание клеймера, история полученных игр) к трём существующим (`view-library`, `view-accounts`, `view-claimer`). |

### 2.3. Что сознательно НЕ трогаем

- `tools/free-games-claimer/` — остаётся вендоренным как есть. Это наш "раннер" (аналог legendary у Heroic): чужой проверенный код, который мы супервизируем извне, а не переписываем.
- `frontend/wailsjs/` — генерируется Wails автоматически.
- `tools/*.cs`, `tools/switcher.exe` — помечаем deprecated, удаляем в Phase E после паритета нативного Go-свитчера.

## 3. Новые зависимости

Принцип PRD — "Native First", поэтому список короткий:

| Зависимость | Зачем | Альтернатива |
|---|---|---|
| `modernc.org/sqlite` (Go, **pure-Go, без CGO**) | Кэш агрегированной библиотеки + история клеймера. Pure-Go критичен: не ломает кросс-компиляцию Wails под Windows/macOS. | Остаться на JSON-файлах — приемлемо, если библиотека < ~1000 игр, но теряем индексацию, инкрементальные обновления и историю. **Рекомендация: SQLite.** |
| `fyne.io/systray` (Go) | Иконка в трее + "сворачивание вместо закрытия" — без этого фоновый планировщик клеймера бессмыслен (Wails v2 не имеет встроенного tray). | Запуск клеймера только при открытом окне (хуже UX). Нужна только в Phase D. |

Чего **не** добавляем и почему:
- **Шифрование:** Windows DPAPI уже реализован через `golang.org/x/sys` (есть в go.mod); macOS Keychain — системный бинарь `security` через `os/exec`. Ноль новых зависимостей.
- **Планировщик:** обычный `time.Ticker` + персист времени последнего запуска. `robfig/cron` не нужен, пока не потребуются cron-выражения.
- **Frontend:** ничего нового. Vanilla JS + Vite остаются; React — отдельное решение вне этого плана.
- **Node.js ≥ 17** остаётся внешним runtime-требованием для клеймера (как и сейчас). В Phase D добавим явную проверку при старте с понятной ошибкой в UI (`findNodePath` уже есть — дополним проверкой версии).

## 4. Контракт общения сервисов с текущей архитектурой

### 4.1. Frontend → Backend (команды)
Существующий механизм Wails bindings, без изменений: фронтенд вызывает методы фасада `App` (request/response). Все 42 текущих метода сохраняют сигнатуры. Новые методы добавляются туда же — после `wails dev`/`wails build` биндинги перегенерируются автоматически.

### 4.2. Backend → Frontend (события воркеров)
Существующий механизм Wails events, но упорядоченный:
- **Сохраняем текущие каналы** для обратной совместимости: `claimer-log`, `claimer-status`, `game-started`, `game-stopped`, `library-updated`.
- **Новые события** — единый конверт `{worker, state, progress, message, data}`:
  - `worker:status` — heartbeat любого воркера (idle/running/error);
  - `library:refresh:progress` — прогресс фонового сканирования по провайдерам;
  - `claimer:claimed` — `{platform, title, account}` при успешном клейме;
  - `switcher:done` — завершение переключения аккаунта.
- Все имена — константами в `internal/bus/events.go` и зеркально в `frontend/src/events.js`. Магические строки запрещены.

### 4.3. Сервис ↔ сервис (внутри Go)
Прямые вызовы методов + `context.Context` для отмены. Долгоживущие воркеры — goroutine'ы, стартующие в `App.Startup(ctx)` и останавливающиеся в `OnShutdown`. Между сервисами нет скрытых зависимостей через глобальные переменные (текущий `appNameCache` в steam.go переедет в library-кэш).

### 4.4. Сервис ↔ внешний раннер (child-процессы)
Формализуем паттерн, который уже стихийно сложился в `RunClaimerScript`: тип `ProcessWorker` в `services/claimer/runner.go` — `exec.Cmd` + построчное чтение stdout + реакции на маркеры (запрос 2FA → Telegram; "claimed" → событие + история) + graceful stop (SIGINT → kill). Тот же тип позже переиспользуем для `legendary.exe` (загрузка/установка Epic-игр, Phase C+).

## 5. Поэтапный план работ

Каждая фаза заканчивается компилируемым приложением, зелёным `go test ./...` и рабочим текущим UI.

**Phase A — Каркас (рефакторинг, ноль новых фич):**
1. `internal/bus` + перенос клеймер-кода из app.go в `services/claimer` (перенос 1:1, без изменений логики).
2. Перенос `GetLibrary` → `services/library`, `monitorGameSession` → `services/monitor`.
3. Переезд настроек в `UserConfigDir` с миграцией.
4. Unit-тесты на перенесённые сервисы с mock-Emitter (требование PRD 4.1).

**Phase B — Переключатель аккаунтов (TcNo):**
5. `internal/vault` (DPAPI/Keychain), шифрование снапшотов fileswap.
6. Capability-интерфейсы; Roblox — в provider-модель; реестр Windows в fileswap.
7. UI: кнопки "снять снапшот текущей сессии" / "восстановить" на карточке аккаунта.

**Phase C — Агрегатор библиотек (Playnite):**
8. SQLite-кэш + фоновый refresh-воркер с прогрессом (UI перестаёт ждать полный рескан).
9. `RemoteLibraryProvider`: Steam (Web API key / XML-профили — частично есть), Epic (уже нативно), GOG.
10. Дедупликация игр между магазинами; бейджи владения по аккаунтам в UI (модель `AvailableOnAccounts` уже готова).
11. (Опционально) подключение `legendary.exe` как раннера установки Epic-игр.

**Phase D — Фоновый клеймер (free-games-claimer):**
12. `scheduler.go`: интервал/время суток, ретраи с backoff, запуск при старте приложения.
13. `history.go`: парсинг результатов → SQLite → событие `claimer:claimed` + Telegram-уведомление (канал уже есть).
14. systray + hide-on-close → честный фоновый режим.

**Phase E — Зачистка:**
15. Удаление C#-легаси (`tools/*.cs`, `switcher.exe`), обновление GEMENI.MD (убрать упоминание React или принять решение о миграции), E2E-тесты UI (PRD 4.1).

## 6. Риски и принятые решения

| Риск | Решение |
|---|---|
| Настройки в CWD у уже существующих пользователей | Миграция при первом старте: читаем из CWD, если в ConfigDir пусто; пишем только в ConfigDir. |
| `legendary.exe` (8 МБ) в git без использования | До Phase C не трогаем; при подключении — рассмотреть download-on-demand вместо хранения бинаря в репо. |
| Клеймер требует системный Node | Проверка версии при старте + понятная ошибка в UI. Бандлинг Node — осознанно за рамками плана. |
| Tray на macOS/Windows ведёт себя по-разному | `fyne.io/systray` тестируем на обеих ОС в Phase D; фича деградирует мягко (без tray планировщик работает при открытом окне). |
| Автоматизация клейма против ToS магазинов | Функция строго opt-in, как в оригинальном free-games-claimer; конфиги/куки не покидают машину (PRD 5.2). |
| Перегенерация Wails-биндингов при каждом новом методе | Методы добавляем только на фасад `App`; внутренние сервисы не биндим. |
