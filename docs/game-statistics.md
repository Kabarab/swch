# Статистика CS2, Dota 2 и Deadlock

В карточке игры, под временем выбранного аккаунта и перед инвентарём, показывается отдельный блок статистики. Просмотр не запускает игру и не переключает Steam. Демо не обращается к реальным источникам.

- **CS2 (730):** Steam Web API, `ISteamUserStats/GetUserStatsForGame/v2`. Убийства, смерти, матчи, победы в матчах, MVP, K/D, процент убийств в голову, точность — только если соответствующие счётчики предоставлены. Счётчики могут включать CS:GO. Premier, Prime, Trust Factor и звание не извлекаются. Нужен `STEAM_WEB_API_KEY` у серверного процесса либо разовый ввод ключа в блоке статистики. Ссылка на получение ключа: <https://steamcommunity.com/dev/apikey>. Введённый ключ передаётся в теле POST и не сохраняется.
- **Dota 2 (570):** OpenDota, `/api/players/{account32}` и `/api/players/{account32}/wl`. Последний известный ранг, место в рейтинге, матчи, победы, поражения, процент побед. Ранг не пересчитывается в MMR. История зависит от покрытия OpenDota и публичности матчей.
- **Deadlock (1422450):** Deadlock API, `/v1/players/{account32}/match-history`. Число доступных уникальных матчей, победы, поражения, процент побед, убийства, смерти, помощь, K/D. Победы/поражения определяются сравнением `player_team` и `match_result` (команды 0/1), как в исходном коде Deadlock API. `player_match_outcome` описывает персональный зачёт и штрафы, поэтому не используется для результата команды. Неизвестные команды/результаты показываются отдельно и исключаются из процента побед. Подробный `/account-stats` не используется: он требует подписки и добавления бота в друзья. История может быть неполной и включать разные режимы.

Для Dota и Deadlock SteamID64 преобразуется в account32 точным целочисленным вычитанием `76561197960265728` после проверки диапазона. При загрузке статистики выбранный идентификатор направляется соответствующему публичному сервису.

## API и кэш

`GET /api/steam/game-stats?account_id=<SteamID64>&app_id=<AppID>&refresh=false`

`POST` по тому же адресу принимает `{ "api_key": "..." }`. Ключ не включается в ответ или локальный кэш. Ошибки HTTP не возвращают URL с ключом.

Ответ содержит идентификаторы аккаунта/игры, `status` (`available`, `partial`, `unavailable`, `needs_key`), `metrics`, `notes`, `source`, `source_url`, время получения, признаки кэша/устаревания. Неизвестные значения — `null`, не ноль. Пустая история стороннего сервиса не подтверждает отсутствие сыгранных матчей. Деление на ноль не создаёт фиктивный K/D.

Используется существующий SQLite-кэш, без изменения схемы. Ключ включает аккаунт и игру. Обычный TTL — 10 минут; ручное обновление и ошибки — 60 секунд. При полном сбое обновления остаётся предыдущая успешная статистика с предупреждением и исходным временем получения. Частичный сбой OpenDota сохраняет доступные поля. Запросы имеют таймаут 15 секунд; переходы по перенаправлениям отключены.

## Проверки

- `cargo test --offline --test steam_game_stats_tests --test steam_library_tests`
- `node tests/ui/game-stats.cjs` (нужен Playwright; путь можно передать через `PLAYWRIGHT_MODULE`).

Проверки используют подставные HTTP-ответы, проверяют расчёты, неизвестные значения, частичные ошибки, кэш, изоляцию аккаунтов при задержке ответа, очистку разового ключа, отсутствие переключения Steam, демо и адаптивный интерфейс. Они не подтверждают доступность закрытых данных конкретного аккаунта у внешних сервисов.

## Локальные данные

Из localconfig.vdf уже читаются Playtime, Playtime2weeks и LastPlayed для каждого доступного локального аккаунта. Полнота и актуальность зависят от кэша Steam. Единого локального источника побед, MMR и K/D всех игр нет. Steamworks ISteamUserStats предоставляет только счётчики, опубликованные разработчиком для конкретной игры; это не универсальный доступ к истории матчей. Разбор сохранений/реплеев требует отдельного адаптера для каждой игры и не гарантирует полную историю.

## Открытие ключа в выбранном аккаунте

Кнопка «Открыть ключ в Steam» вызывает существующий POST /api/steam/switch-account с account_id выбранной карточки и фиксированным open_url https://steamcommunity.com/dev/apikey. Steam переключает аккаунт и открывает страницу в своём браузере один раз. При истекшей сессии Steam может запросить вход/Steam Guard. Ключ копируется вручную. Если выбранный аккаунт не имеет ключа, Steam покажет форму регистрации; SWCH не заполняет и не отправляет её. Ответ Steam о слишком частых запросах также не является отсутствием ключа: нужно дождаться снятия ограничения, а не повторять открытие страницы.

При разовом вводе пользовательского ключа дополнительно запрашивается `GetPlayerBans` через публичный `api.steampowered.com`. Уже имеющийся пользовательский ключ можно применять для проверки публичного статуса других SteamID: создавать отдельный ключ для каждого аккаунта не требуется. Партнёрский `partner.steam-api.com` требует ключ издателя: запросы к нему с пользовательским ключом возвращают 403 и подвергаются строгим ограничениям по IP. Сохраняются ограничения, но не ключ. Если ответ Steam содержит `bans` с одинаковыми положительными `AppIdMin` и `AppIdMax`, игра определяется по этому AppID и её название берётся из библиотеки Steam, когда оно там есть. Диапазон AppID или одно лишь число банов не позволяют определить игру: её можно указать в «Настроить ограничения» по данным Steam Support. Известные игры сохраняются при следующих проверках без списка AppID. Ошибка проверки не считается отсутствием бана.

<https://help.steampowered.com/en/wizard/VacBans> показывает детали только после входа владельца. Страница открывается в браузере клиента Steam, но её авторизованное содержимое не доступно локальному HTTP-приложению SWCH. Вход в Steam сам по себе не даёт SWCH AppID бана: для автоматического определения нужен точный AppID из ответа Steam Web API.

Автоматическая проверка ограничений при запуске SWCH повторяется для каждого аккаунта не чаще одного раза в 15 минут, даже после перезагрузки страницы; неудачная попытка также учитывается, чтобы не усиливать временные ограничения Steam. Явная проверка выбранного аккаунта по кнопке не ограничивается этим интервалом.
