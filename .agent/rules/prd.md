Product Requirements Document (PRD): swch (Antigravity)
Версия: 1.0 Статус: Draft Дата: 05.02.2026 Проект: Cross-platform Multi-Launcher & Account Switcher

1. Общее описание (Executive Summary)
   swch — это десктопное приложение (Windows/macOS) для объединения игровых библиотек из всех популярных магазинов цифровой дистрибуции. Ключевая особенность — бесшовное переключение аккаунтов (Hot-Swap) без ввода паролей и 2FA для поддерживаемых платформ. Проект строится на принципе "Native First" (минимум внешних зависимостей) и агрессивном автоматизированном тестировании (AI-driven QA).

2. Цели и Метрики (Goals & Success Metrics)
   2.1. Бизнес-цели

Создать "Единый Хаб" для геймеров, у которых игры разбросаны по разным магазинам.

Устранить трение при смене аккаунтов (для семей, киберспортсменов, бустеров).

2.2. Критерии охвата (The "80k+" Rule)

Поддержка интеграции (сканирование + запуск) для любого игрового лаунчера, имеющего более 80,000 скачиваний в мире. Priority Tier 1: Steam, Epic Games Store, Battle.net, Ubisoft Connect, EA App. Priority Tier 2: GOG Galaxy, Riot Client, Wargaming.net, Itch.io, Roblox, Minecraft Launcher. Priority Tier 3: Amazon Games, Legacy Launchers (Bethesda - migrated).

2.3. Автономность разработки (AI & QA)

Zero-Manual QA: Код должен покрываться тестами автоматически при генерации.

Self-Healing: Система должна уметь обнаруживать изменения в API лаунчеров (через падение тестов) и предлагать фиксы.

3. Функциональные требования (Functional Requirements)
   3.1. Ядро (Core System)

Стек: Go (Backend) + Wails v2 + React/Vite (Frontend).

OS: Windows 10/11, macOS (Silicon/Intel).

Discovery: Автоматическое обнаружение установленных лаунчеров и игр на всех дисках (используя internal/scanner).

3.2. Менеджер Аккаунтов (Account Switcher)

Для каждого поддерживаемого лаунчера приложение должно уметь:

Extract: Извлекать текущую сессию (токены, конфиги) из файлов лаунчера.

Store: Сохранять сессию локально в зашифрованном виде (DPAPI на Windows, Keychain на macOS).

Swap: Подменять файлы конфигурации лаунчера для смены пользователя.

Требование: Корректное завершение процесса лаунчера (Kill Process) перед подменой.

Требование: Работа с реестром (Windows) и plist (macOS), если лаунчер хранит данные там.

3.3. Агрегатор Библиотеки (Library Aggregator)

Отображение единого списка игр ("Все игры").

Фильтрация по магазину (Source).

Запуск игры напрямую (через URI Scheme steam://, com.epicgames.launcher:// или прямой вызов exe с аргументами).

4. Требования к ИИ-разработке и Тестированию (AI-Driven QA)
   Поскольку требуется, чтобы ИИ тестировал код сам, в архитектуру закладывается AI QA Agent Protocol.

4.1. Уровни тестирования

ИИ при написании кода обязан генерировать тесты трех уровней:

Unit Tests (Go): Для всей бизнес-логики (internal/epic, internal/scanner).

Правило: Никакой код не принимается без \_test.go.

Integration Tests (Mocking):

Поскольку мы не можем создавать реальные аккаунты на серверах Steam/Epic (капча, бан по IP, SMS-верификация), ИИ должен создавать Mock-серверы и Mock-файловые системы.

Сценарий: ИИ генерирует структуру папок, имитирующую установленный Steam, и проверяет, что сканер корректно находит в ней игры.

E2E (End-to-End):

Использование Playwright или схожего инструмента для тестирования UI Wails приложения.

4.2. Протокол "Виртуального Пользователя"

Вместо создания реальных аккаунтов (что невозможно автоматизировать легально), реализуется система "Test Fixtures Injection":

ИИ генерирует набор "фейковых" конфигов (loginusers.vdf для Steam, .dat файлы для Epic) с заведомо известной структурой.

Тест проверяет, что swch корректно парсит эти файлы, "шифрует" их и "восстанавливает" обратно.

5.2. Безопасность данных

Токены и сессии никогда не покидают устройство пользователя.

При "сбросе" данных в файл, они должны шифроваться ключом, привязанным к железу пользователя.

7. Правила для ИИ (System Prompt Directive)
   При работе над задачами этого проекта ИИ должен следовать этим директивам:

Не спрашивать "как сделать": Если задача — "Добавить поддержку Ubisoft", ИИ ищет документацию по структуре файлов Ubisoft, пишет код сканирования, пишет код подмены файлов и пишет тест на мок-файлах.

Mock Everything: Если для теста нужен установленный лаунчер, ИИ пишет код, который создает временную папку с фейковыми файлами лаунчера, прогоняет тест и удаляет её.

Cross-Platform Check: Любой код, работающий с путями или процессами, должен иметь реализацию \_windows.go и \_darwin.go.
